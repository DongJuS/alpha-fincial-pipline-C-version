# P3 — C nonblocking drivers (run-up to MVP-2)  (Phase 3)

## Goal
Give the core its real I/O paths against the shared Docker Postgres/Redis, on the
libwebsockets-owned loop, and emit the driver benchmark that decides the **MVP-2
driver-I/O GO/NO-GO** stop gate. Delivered as verifiable sub-units.

## Sub-units (incremental, each committed + CI-gated)
1. **KRX trading-calendar core (this unit, pure/no-I/O).** Port
   `next_trading_day_start` (weekend-only, exact parity) plus a holiday-aware
   safety variant used by the breaker-lockout expiry. Golden-parity the
   weekend-only path; unit-test the holiday-aware fail-closed path.
2. **Redis cache driver (hiredis).** `latest_ticks:{ticker}` get/set and the L3
   breaker lockout: absolute `expires_at` = next KRX session 09:00 KST (unit 1)
   with matching TTL; fail closed on missing/stale `krx:holidays:{year}`.
   Integration test against Docker Redis (lockout persists across restart, stays
   closed through weekends/holidays, releases only at the next session).
3. **Postgres driver (nonblocking libpq, bounded pipeline).** Typed queries for
   the in-scope tables; `aggregate_risk` SQL totals match a Python golden.
   Integration test against Docker Postgres.
4. **HTTP (libcurl-multi) seam.** Telegram POST + optional LLM POST client only.
5. **LWS-loop integration + driver benchmark.** All three drivers readiness-driven
   by the single LWS loop (per the P0 spike). Emit `db-read-write` and
   `redis-hot-path` at concurrency 1/8/32 → the MVP-2 primary-metric decision.

## Contract
`docs/MODULE_SPECS.md §5,§6`, `docs/plans/phase-3-drivers.md`, Python
`src/utils/market_hours.py`, `redis_client.py`, `db_client.py`, `queries.py`.
KST is a fixed UTC+9 (no DST), so calendar math is pure integer epoch arithmetic.

## MVP-2 gate (STOP)
GO requires a statistically repeatable primary-metric win over ≥30 order-rotated
trials (95% bootstrap CI excludes parity) with no correctness/error/drop/resource/
safety regression. NO-GO → ship the C numeric+decision core as a library and keep
Python for I/O. Risk/order logic never runs on bounded workers.

## Unit 1 tests
`next_trading_day_start`: Fri/Sat/Sun/mid-week → next weekday 09:00 KST (parity
golden, epoch-exact). Holiday-aware: skips supplied holidays; returns the
fail-closed sentinel when the candidate day is outside calendar coverage.
