# P2 (part 3, final) — screener deterministic filter  (Phase 2)

## Goal
Port the non-RL screener decision logic (`_score_ticker` + selection) as pure,
no-I/O C functions with golden parity. This closes the P2 §7 indicators/screener
contract. Ranking (`ranking_calculator`) is pure `ORDER BY`+enumerate over DB
rows and is grouped with the P3 aggregate-SQL work, not the numeric core.

## Files
- `core/include/alpha/screener.h`, `core/src/indicators/screener.c`
- Fixture `bench/fixtures/screener-cases.json`
- Golden `core/tests/golden/screener-cases.json` via `generate_golden_decisions.py`
- Test `core/tests/test_screener.c`

## Contract
`docs/MODULE_SPECS.md §7`, Python `src/agents/screener.py` @ `3642cdc…`:
- `_score_ticker(bars, vol_th, pct_th)`: today=bars[0], past=bars[1:];
  avg_volume=mean(past) or 0; volume_ratio=today/avg or 0; change=abs(today.change or 0);
  passes = ratio>=vol_th OR change>=pct_th; score = ratio/vol_th + change/pct_th.
- `_evaluate`: bars<5 (`_MIN_DATA_DAYS`) → not passing.
- selection: keep passing, stable sort by score desc, take top `MAX_SCREENED_TICKERS`(10).
- Constants: volume-surge 2.0×, change-pct 3.0% (`constants.h`).

## Parity note
`screener.py` imports DB/logging at module load, so like the risk gates the
golden generator transcribes the pure `_score_ticker`+selection arithmetic
line-for-line from the pinned source (recorded in MEMORY). C matches under dev+bench.

## Tests
Boundaries: ratio exactly 2.0 and change exactly 3.0 (both pass, `>=`); volume-only
vs change-only pass; insufficient data (<5 bars) → skip; null change → 0; selection
top-N with stable tie order and cap > candidate count.
